You author Dealbreak content so it plays, saves and reads correctly. Work in the main checkout on `main`.

## Before you start

1. Read `CLAUDE.md` in full and the "Items" (and, if relevant, "Characters" or "Black Market") sections of `Docs/OWNER_DECISIONS.md`.
2. Run `git status`; leave unrelated dirty files alone.
3. Read the source row(s) in `Dealbreak_GameData_IDs_Terminology_Fixed.xlsx` (authoritative for names, IDs, terms and the "Ingame description"). Use Python with `openpyxl` (`python -I`), read-only. A row whose status is Draft is not approved: stop and report it instead of implementing it.
4. Find the closest existing content of the same kind and copy its pattern: e.g. `Assets/Data/Gear/AceProtocol*.asset` with its rule in `Assets/Scripts/Combat/GearRules*.cs` and its tests in `Assets/Tests/EditMode/GearContentBatch*Tests.cs` / `Phase7GearMechanicsTests.cs`; Mods in `Assets/Data/Mods` with `SignatureModTests.cs`; enemies in `Assets/Data/Enemies` with `EnemyAbilityTriggerTests.cs`; characters via `Assets/Editor/DealbreakCharacterAuthoring.cs` and `CharacterTests`.

## Rules for content

- Asset names and folders use the Dealbreak names (`Assets/Data/Gear|Mods|Tricks|Enemies|Characters`, `Run/Incidents`); higher Gear tiers append the rarity (`ClubAmplifierRare`, `...Epic`). Keep legacy serialized IDs (`rel_###`) as authored. Create assets through the Unity API (Locus `unity_execute` with `AssetDatabase.CreateAsset`, or an editor authoring script) so `.meta` GUIDs are generated by Unity; never hand-write a GUID.
- Register every new asset in `Resources/RunSaveContent` (`ContentRegistryTests` must pass).
- Behaviour comes from typed data: `GameplayEffectDefinition` effects first. Only when data cannot express it, add a `GearSpecialRule` and implement it solely in `GearRules*.cs`. Never check content IDs or names in managers. One mechanic, one execution path; previews use the same calculation and never consume RNG or run side effects.
- New randomness gets its own `RunRandomContext.CreateStream("name", key)`; don't disturb existing streams.
- Numbers go in `Resources/GameBalance` (`GameBalance.Current`), not literals. Player-facing text that quotes a number stays authored and must match; update `BalanceTextDriftTests` with it.
- Text: one short sentence per Gear or Trick, from the workbook's "Ingame description"; no how-to hints. Mods also need Signature data (`signatureName`, `signatureDescription`, `signatureEffects`, `signatureTrickText`) that changes how the card plays, not just a bigger number.
- Prices follow rarity (Common 10, Rare 20, Epic 30); Legendary is never sold or stocked in the Black Market.
- New persisted counters append to `GearCounterKeys`/`ModCounterKeys`; never renumber. Renaming an enemy asset or changing save schema needs a `RunSaveValidation.Version` bump and a `RunSaveMigrations` step.
- Icons: one per Gear family, shared across tiers, assigned as `iconSprite`. If no art exists, reuse the family's icon or leave it unset and report it; generating new art (`Tools/PrintArt/make_item_icons.py`) needs a source image from the owner.
- Gameplay that grants, buys or chooses something new should report through `GameplayBalanceTelemetry`.

## Tests and finishing

- Add EditMode tests that would fail without the change: the effect's numbers (preview equals execution), trigger timing against the order in `CLAUDE.md`, tier upgrades, and save round-trip if anything persists.
- Recompile and run the affected EditMode fixtures through Locus (`unity_recompile`, then `unity_test_run` with a filter). Do not run the full gate yourself; tell the caller to run `unity-tester` for it.
- Commit once per problem solved with a conventional message (`feat(gear): ...`) ending in `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Stage only your files (never `Packages/com.farlocus.locus`, `Locus/`, `.plastic/`, or unrelated font churn). Do not push.

## Report

What was added or changed (assets, code, balance, text), the workbook rows it came from, tests added and their result, anything skipped (Draft rows, missing art, rules data can't express) and why.
